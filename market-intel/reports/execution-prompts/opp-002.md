# NI Windsor Framework Trade Documentation AI — Execution Brief

> AI-powered customs declaration assistant for Northern Ireland businesses navigating the unique Windsor Framework rules for GB-NI-EU cross-border trade.

## Product Vision

### What it does
Accepts commercial invoices, packing lists, and CMR documents uploaded by NI-based exporters/importers, extracts all shipment data using AI, runs a Windsor Framework eligibility decision tree to determine goods-at-risk status, and generates a CDS-ready customs declaration draft at a fraction of the cost of a customs broker.

### Who it serves
NI-based manufacturing and trading SMEs with 2-50 employees doing regular cross-border movements: NI → GB, GB → NI, NI → EU (Ireland), EU → NI. Food producers, engineering firms, distributors with regular shipment volumes of 10-200 per month.

### Why it matters
Average customs declaration costs £48 via a broker. The UK's total customs admin burden was £1.8B in 2022. CHIEF was decommissioned December 2024 — all declarations now require CDS-compatible software. NI businesses face a uniquely complex situation: dual EORI (GB + XI), Windsor Framework goods-at-risk determination per shipment, and rapidly evolving rules. No NI-specific tool exists. This product saves £30-40 per declaration vs. broker costs and eliminates errors from manual CDS entries.

## MVP Requirements (4-week scope)

### Core features
1. Document upload portal (invoice, packing list, CMR — PDF and image)
2. Claude API extraction of shipment fields (consignee, consignor, commodity descriptions, weights, values, country of origin)
3. Windsor Framework decision wizard (step-by-step goods-at-risk determination)
4. Commodity code lookup (against HMRC Trade Tariff API)
5. CDS declaration draft — all fields populated, output as structured PDF or JSON
6. Validation layer: flag missing fields, suspicious commodity codes, value mismatches
7. Declaration history per customer (audit trail)

### User flows

**Flow 1: New declaration from document upload**
1. Upload invoice + packing list
2. AI extracts: consignee, consignor, EORI numbers, commodity descriptions, HS codes (if present), total value, currency, incoterms, country of origin, net/gross weight
3. User reviews and corrects extracted fields (inline edit)
4. Windsor Framework checker: "Is this movement NI→GB, GB→NI, or NI→EU?" → follow-on questions to determine goods-at-risk
5. Commodity code lookup: AI suggests codes, user confirms
6. System generates CDS import or export entry (C88/E2 format) as PDF
7. User downloads PDF and submits via CDS portal (MVP — no direct API submission)

**Flow 2: Repeat shipment shortcut**
1. Select prior declaration as template
2. Update date, quantities, and values
3. Re-validate and generate new declaration in under 2 minutes

**Flow 3: Windsor Framework checker (standalone)**
1. Answer 5 questions about movement type, goods category, and business status
2. Receive determination: at-risk / not-at-risk with explanation and citation

### Required screens/pages
- Dashboard: recent declarations, pending validations, monthly stats
- New declaration: upload → extract → review → wizard → output
- Declaration history: searchable list with status and download links
- Windsor Framework checker: standalone wizard tool
- Company settings: EORI numbers (GB + XI), default commodity codes, frequent counterparties
- Help/guide: Windsor Framework explainer, CDS field reference

### Admin functionality
- Customer management (multi-company support for accountants/brokers serving multiple NI businesses)
- Declaration audit log (who submitted what, when)
- Error pattern monitoring (which fields are most often corrected post-extraction)

### Authentication
- Email + password with MFA for MVP
- Company-level accounts with multiple user seats

### Billing
- Stripe integration
- Two tiers: Pay-per-declaration (£12/declaration) and Monthly subscription (£199/month unlimited)
- 10 free declarations on signup (no card required)

## Technical Architecture

### Frontend
- Next.js 14 (App Router)
- Tailwind CSS + shadcn/ui components
- PDF.js for document preview
- React Hook Form for declaration field editing
- Deployed on Vercel

### Backend
- Next.js API routes + separate Node.js service for document processing
- PostgreSQL (Supabase or Railway) for declaration data
- S3-compatible storage (Cloudflare R2 or AWS S3) for uploaded documents
- Background jobs via Inngest or BullMQ for async AI extraction

### Database
- `companies`: id, name, gb_eori, xi_eori, billing_plan
- `declarations`: id, company_id, movement_type, goods_at_risk, status, created_at
- `declaration_fields`: declaration_id, field_name, extracted_value, confirmed_value, source
- `documents`: id, declaration_id, type (invoice/packing_list/CMR), s3_key, extraction_status
- `commodity_codes`: code, description, last_validated_at

### API requirements
- **HMRC Trade Tariff API**: Free, public. Used for commodity code lookup and validation. No auth required.
- **HMRC CDS API**: Developer registration required. Used for live submission (week 5+ feature). Rate limits apply.
- **Claude API (Anthropic)**: Document extraction. Expected volume: 50-200 API calls/day at launch. Estimated cost: £50-150/month.

### AI model usage
- **Document extraction prompt**: Upload invoice image/PDF → extract structured JSON of all shipment fields. Use `claude-sonnet-4-6` with vision capability.
- **Commodity code suggestion**: Given product description → suggest top 3 HS codes with confidence scores.
- **Windsor Framework assistant**: Conversational Q&A for edge cases not covered by the decision tree.
- **Expected volumes at 100 declarations/month**: ~300 Claude API calls (3 per declaration average). Cost ~£15-30/month.

### Hosting
- Vercel (frontend + API routes): ~£20/month
- Railway (PostgreSQL + background jobs): ~£30-50/month
- Cloudflare R2 (document storage): ~£5/month
- Total infra: £55-75/month at launch scale

### Scalability
- MVP assumptions hold to ~500 declarations/month. Beyond that, separate the extraction service and add a proper job queue.
- CDS live submission (not in MVP) requires HMRC developer registration (4-8 week process — start this on day 1).

## Data Model

### Core entities
- **Company**: NI business using the platform. Has GB EORI and XI EORI. Billing tier.
- **Declaration**: One customs entry per shipment. Links to company, documents, and extracted fields.
- **Document**: Uploaded file (invoice, packing list, CMR). Has extraction status and S3 key.
- **DeclarationField**: Individual field extracted from documents (key-value with source and confidence).
- **CommodityCode**: Cached HMRC tariff entries with last-validated timestamps.

### Important metadata
- All documents encrypted at rest (GDPR — commercial invoices contain sensitive trade data)
- Soft deletes on declarations (never hard-delete, needed for audit trails)
- Audit log table: every field change, who made it, when

## AI Usage Details

### Where AI adds value
1. **Document extraction**: Pulling structured fields from unformatted commercial invoices (the hardest, most time-consuming manual step)
2. **Commodity code suggestion**: HS code lookup from plain English product descriptions
3. **Windsor Framework edge case Q&A**: Conversational assistant for unusual movement types
4. **Declaration validation**: Flagging suspicious combinations (e.g., declared value vs. commodity code mismatch)

### Where deterministic systems are better
- Windsor Framework decision tree: the core at-risk/not-at-risk determination must be rules-based and auditable, not AI-generated. Use a clearly documented decision tree with citation to HMRC guidance.
- Duty calculation: always use HMRC Trade Tariff API rates, never AI estimation
- CDS field format validation: rules-based regex/schema validation, not AI

### Prompting suggestions
```
System: You are a customs document data extraction specialist. Extract all shipment fields from the uploaded document. Return a JSON object with fields: consignor_name, consignor_address, consignor_eori, consignee_name, consignee_address, consignee_eori, commodity_descriptions (array), hs_codes (array if present), total_value, currency, incoterms, country_of_origin, net_weight_kg, gross_weight_kg, number_of_packages, invoice_number, invoice_date. Mark any field as null if not found. Flag confidence as high/medium/low per field.

User: [attached document]
```

Use `claude-sonnet-4-6` with extended thinking disabled (speed > depth for extraction). Temperature 0.
