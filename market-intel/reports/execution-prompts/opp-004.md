# Food Allergen & PPDS Compliance Manager — Execution Brief

> The simplest way for small UK food businesses to manage allergen declarations, generate PPDS labels, and stay compliant with Natasha's Law — from £19/month.

## Product Vision

### What it does
A web app for small food businesses (delis, bakeries, caterers, farm shops, food trucks, school kitchens) that maintains an ingredient database with allergen flags, builds recipes with automatic allergen matrix generation, produces PPDS-compliant labels as printable PDFs, parses supplier allergen declarations using AI, and generates QR codes for digital allergen disclosure on menus.

### Who it serves
Owners and managers of small UK food businesses preparing food on-site: artisan bakeries, delis, small caterers, farm shop food producers, school/college kitchen managers, food truck operators. Businesses that sell food directly to consumers with 1-20 employees, doing their own food production.

### Why it matters
PPDS (Prepacked for Direct Sale) guidance updated March 2025 requires full ingredient lists with 14 allergens clearly emphasised on labels for foods prepared and packaged on-site. Criminal liability under Natasha's Law applies. FSA enforcement activity is increasing. The UK has 400,000+ food businesses of this type. Most use paper recipe cards or spreadsheets. No dominant, affordable tool (sub-£50/month) has emerged — the market is filled with enterprise tools (Nutritics, £200+/month) or partial solutions.

## User Personas

### Primary: Small Food Business Owner/Manager
- **Context**: Runs a deli or bakery with 2-8 staff. Makes 20-60 different products. Has a ring binder with hand-written recipes and a spreadsheet trying to track allergens. Understands the legal requirement but the process is too slow for their daily workflow.
- **Pain points**:
  - If a recipe changes (ingredient substitution when a supplier is out), updating allergen info is manual and easy to forget
  - Supplier allergen declarations arrive as PDFs — extracting the data is tedious
  - Printing allergen labels is done with a Word template that's prone to error
  - EHO inspector visited last year and said their allergen records were "adequate but not ideal"
  - QR code for digital disclosure — knows it's possible but hasn't set it up
- **Success looks like**: When a recipe changes, allergen matrix updates automatically. Label prints in 60 seconds. EHO inspection produces zero allergen findings.

### Secondary: School/College Kitchen Manager
- **Context**: Responsible for feeding 200-600 students daily. Has multiple daily menu items with complex allergen profiles. Special dietary requirements for some students. Under pressure from the school's H&S officer.
- **Pain points**:
  - Must produce allergen information for every dish on every day's menu
  - Student allergies must be cross-referenced with the day's menu
  - Paper-based or spreadsheet system is error-prone and time-consuming to maintain

## MVP Requirements (4-week scope)

### Core features
1. Ingredient database with 14-allergen flags (per FSA list: celery, cereals with gluten, crustaceans, eggs, fish, lupin, milk, molluscs, mustard, nuts, peanuts, sesame, soybeans, sulphur dioxide)
2. Supplier declaration upload: PDF upload → AI extracts allergen information → pre-fills ingredient record
3. Recipe builder: add ingredients with quantities → system generates full allergen matrix automatically
4. PPDS label generator: recipe → PDF label with ingredient list and emphasised allergens
5. Allergen matrix view: all recipes vs. all 14 allergens in a grid
6. QR code generator: link to a hosted digital allergen page per menu/recipe

### User flows

**Flow 1: Add an ingredient**
1. Enter ingredient name
2. Toggle the 14 allergen flags (or upload supplier declaration PDF for AI extraction)
3. If PDF uploaded: AI extracts allergen presence/absence per allergen — user confirms
4. Ingredient saved to database with allergen profile

**Flow 2: Build a recipe**
1. Create recipe: name, category (food group), portion size
2. Add ingredients from database (search, quantity)
3. System automatically generates allergen matrix from ingredient profiles
4. If any allergen is present: shown in recipe header and emphasised in ingredient list
5. Recipe saved; label available immediately

**Flow 3: Generate a PPDS label**
1. Select recipe
2. Choose label size (standard A6, small A7, or custom)
3. Label preview shows: product name, ingredient list (allergens in bold/caps), allergen summary line, business name, date
4. Download PDF for printing on standard label paper or printer

**Flow 4: Digital allergen disclosure (QR code)**
1. Select menu or recipe group
2. System generates a hosted public page listing all items with their allergen matrix
3. QR code generated — stick on chalkboard, print on menu, share with customers
4. Page updates automatically when recipes change

### Required screens/pages
- Dashboard: total recipes, last updated date, any recipes with missing supplier declarations
- Ingredient database: searchable list with allergen badges, upload declaration button
- Recipe list: grid view with allergen summary per recipe
- Recipe editor: ingredient picker, live allergen matrix update
- Label generator: template preview, download PDF
- Allergen matrix: full grid (recipes × 14 allergens) — exportable for EHO
- Digital menu: hosted public page for QR code
- Settings: business name, address (for labels), label size preference

### Admin functionality
- Multiple menu/site support (catering companies serving different venues)
- User roles: Owner (full access) vs. Staff (view and print labels only)
- Audit log: who changed which recipe and when

### Authentication
- Email + password
- Free tier: 5 recipes, no time limit (hook for small operators)
- Paid tiers require card

### Billing
- **Free**: up to 5 recipes, 1 user, basic labels
- **£19/month**: unlimited recipes, 1 site, QR code menus, supplier declaration upload
- **£39/month**: multi-site (up to 5 locations), multiple users, CSV/PDF export
- Annual billing: 2 months free

## Technical Architecture

### Frontend
- Next.js 14, Tailwind CSS + shadcn/ui
- Allergen matrix uses a simple CSS grid — no charting library needed
- QR code: `qrcode` npm library
- Label PDF: react-pdf or PDFKit server-side
- Vercel deployment

### Backend
- Next.js API routes
- PostgreSQL (Railway) — ingredient and recipe data is relational (many-to-many)
- Cloudflare R2 for supplier declaration PDF storage
- No complex background jobs needed (no scheduled tasks in MVP)

### Database
- `companies`: id, name, address, billing_plan
- `ingredients`: id, company_id, name, allergens_json (bitmask or JSON of 14 flags), supplier_name
- `supplier_declarations`: id, ingredient_id, s3_key, extracted_at, extraction_confidence
- `recipes`: id, company_id, name, category, portion_size, last_updated
- `recipe_ingredients`: id, recipe_id, ingredient_id, quantity, unit
- `labels_generated`: id, recipe_id, generated_at, template_size (audit log)
- `digital_menus`: id, company_id, slug, recipe_ids_json, qr_code_url

### API requirements
- **Claude API**: Supplier declaration PDF extraction. Parse a food manufacturer's allergen declaration PDF and return structured JSON: `{ingredient_name, allergens_present: string[], allergens_absent: string[], may_contain: string[], confidence: string}`. Volume: 10-50 calls/day at launch. Cost: ~£5-15/month using `claude-haiku-4-5`.
- **FSA Open Food Facts API (optional)**: Public ingredient database — pre-seed common ingredients with allergen data to reduce manual entry for first-time users.
- No payment-side APIs beyond Stripe.

### AI model usage

**Supplier declaration extraction prompt:**
```
System: You are a food allergen specialist. Extract allergen information from this supplier allergen declaration document. Return JSON: {ingredient_name: string, definitely_contains: string[], definitely_free_from: string[], may_contain: string[], notes: string, confidence: "high"|"medium"|"low"}. Use the 14 EU/UK mandatory allergens: celery, cereals_with_gluten, crustaceans, eggs, fish, lupin, milk, molluscs, mustard, nuts, peanuts, sesame, soybeans, sulphur_dioxide.

User: [PDF content or image]
```

Use `claude-haiku-4-5` for cost. Test against 20+ real supplier declaration formats (these vary enormously) before launch.

**Important**: Never use AI for the allergen matrix calculation itself. Once an ingredient's allergens are in the database (human-confirmed), the recipe allergen matrix is pure set-union arithmetic. This must be deterministic and auditable.

### Hosting
- Vercel: £20/month
- Railway: £15-25/month
- Total: ~£35-45/month (low infra cost — mostly static/relational data)

## Data Model

### Core entities
- **Ingredient**: A single ingredient with 14-allergen flags. The atomic unit of the whole system.
- **SupplierDeclaration**: The uploaded document that was the source of an ingredient's allergen data. Audit evidence.
- **Recipe**: A collection of ingredients with quantities. Allergen profile is derived, not stored (always recalculated from ingredients).
- **DigitalMenu**: A public-facing page grouping recipes for QR code disclosure.

### Important metadata
- Recipe allergen profile is ALWAYS recalculated dynamically from ingredient records — never cached independently. This ensures recipe automatically updates when an ingredient's allergen status changes.
- `supplier_declarations` preserved permanently — FSA may ask for evidence of due diligence
- Audit log of recipe changes (who changed what ingredient, when) — important for liability

## AI Usage Details

### Where AI adds value
1. **Supplier declaration parsing**: Manufacturer allergen declarations arrive in wildly different formats. AI handles unstructured PDFs that a regex-based approach cannot.
2. **Ingredient auto-suggestion**: When a user types "whole milk", AI can suggest the known allergen profile (milk) before they confirm.

### Where deterministic systems are better
- **Allergen matrix calculation**: Pure set arithmetic from ingredient records. Never AI.
- **Label text generation**: Template-based, not AI. The format is legally defined.
- **Billing and auth**: Standard libraries.

### Quality bar for AI extraction
Target >90% accuracy on allergen extraction before launch. Test against at least 50 different supplier declaration documents. For any ingredient where confidence is "low", flag for manual review rather than auto-saving. An incorrect allergen flag that reaches a label is a safety incident, not just a software bug.
