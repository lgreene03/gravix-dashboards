## 1. Objective

The repository has **no LICENSE file**, which means it is legally all-rights-reserved and nobody
may use, copy, or distribute it. After this spec, the repository carries the full Apache-2.0
licence text, a per-directory licence map, a copyright notice, and an SPDX identifier on every
first-party source file.

## 2. Context the implementer needs

- Repository root contains no `LICENSE`, `LICENCE`, `COPYING`, or `NOTICE` file. Verified: `ls LICENSE*` returns nothing.
- Go module path is `github.com/lgreene/gravix-dashboards` (`go.mod:1`).
- First-party Go source lives in: `services/`, `transforms/`, `pkg/`, `schemas/`, `cmd/`, `tests/`, `terraform-provider-gravix/`.
- Generated code lives in `gen/gravix/v1/gravix.pb.go` — generated by protoc, must NOT receive a hand-written header.
- Vendored third-party code lives in `sdk/node/node_modules/` — must NOT be touched.
- `sdk/go/`, `sdk/python/`, `sdk/node/` are first-party SDK source (excluding `node_modules/`).
- Copyright holder for all files: `The Gravix Authors`.

## 3. Non-goals for this spec

- Do NOT create `ee/` or any BUSL file. That is GRVX-702.
- Do NOT create `boundary.yaml`. That is GRVX-703.
- Do NOT add CI enforcement of headers. That is GRVX-704.
- Do NOT modify `gen/gravix/v1/gravix.pb.go` — regenerating it would discard a hand-added header.
- Do NOT modify anything under any `node_modules/` directory.
- Do NOT change the module path, package names, or any code logic. This spec adds comments and files only.

## 5. Interface contract

### 5.1 `LICENSE`

The exact, unmodified text of the Apache License, Version 2.0, as published at
`https://www.apache.org/licenses/LICENSE-2.0.txt`. Do not reword, reformat, or abridge any part of
it, including the appendix. The file's final line is the appendix's closing `limitations under the License.`

### 5.2 Go / JS / TS / proto header (exactly these 3 lines, then one blank line)

```
// Copyright 2026 The Gravix Authors
// SPDX-License-Identifier: Apache-2.0
```

For `*.go` files the header goes **above** the `package` clause. If a build constraint comment
(`//go:build`) is present, the header goes **above** the build constraint, followed by a blank
line, then the build constraint, then a blank line, then `package`.

### 5.3 Python header (exactly these 2 lines, then one blank line)

```
# Copyright 2026 The Gravix Authors
# SPDX-License-Identifier: Apache-2.0
```

If the file's first line is a shebang (`#!`), the header goes immediately **after** the shebang.
If the file's first line is an encoding declaration (`# -*- coding:`), the header goes after it.

### 5.4 `NOTICE`

```
Gravix
Copyright 2026 The Gravix Authors

This product includes software developed by The Gravix Authors
(https://github.com/lgreene03/gravix-dashboards).
```

### 5.5 `LICENSES.md`

A markdown table with exactly these rows, in this order:

| Path | Licence |
|---|---|
| `/` (all paths not listed below) | Apache-2.0 |
| `ee/**` | BUSL-1.1, Change Date = release + 2 years, Change Licence = Apache-2.0 |
| `sdk/**` | Apache-2.0 |
| `proto/**` | Apache-2.0 |
| `deploy/**` | Apache-2.0 |
| `terraform-provider-gravix/**` | Apache-2.0 |
| `docs/**`, `docs-site/**` | CC-BY-4.0 |
| `gen/**` | Apache-2.0 (generated from `proto/`) |
| `**/node_modules/**` | Third-party; see each package |

Followed by this paragraph verbatim:

> `ee/` does not exist yet. When it does (GRVX-702) it is **source-available**, not open source.
> Everything else in this repository is open source under an OSI-approved licence and, per the
> Open-Core Charter §7.3 Q4, cannot be relicensed.

### 5.6 `scripts/add_license_headers.sh`

```bash
#!/usr/bin/env bash
# Adds SPDX licence headers to first-party source files. Idempotent.
# Usage: ./scripts/add_license_headers.sh [--check]
#   (no args)  add missing headers in place
#   --check    exit 1 and list files missing a header; modify nothing
set -euo pipefail
```

Exit codes: `0` = all files have headers (or were fixed); `1` = `--check` found missing headers;
`2` = invalid argument.

`--check` prints one path per line to stdout for each file missing a header, then
`<n> file(s) missing a licence header` to stderr.

## 6. Behaviour

1. Write `LICENSE` with the verbatim Apache-2.0 text.
2. Write `NOTICE` with the §5.4 content.
3. Write `LICENSES.md` with the §5.5 content.
4. Write `scripts/add_license_headers.sh` implementing §5.6 and `chmod +x` it.
5. The script determines the file set as: all files matching the extensions in §4.2 under the
   listed directories, minus every path listed in §4.3.
6. For each file in the set, the script checks whether the literal string
   `SPDX-License-Identifier: Apache-2.0` appears in the **first 5 lines**. If it does, the file is
   skipped (this is what makes the script idempotent). If it does not, the correct header for the
   file's extension is inserted per §5.2 or §5.3.
7. Run `./scripts/add_license_headers.sh` once.
8. Run `gofmt -l .` and confirm it lists no first-party file. If a `.go` file is now unformatted,
   the header was inserted in the wrong position — fix the insertion, do not run `gofmt -w`.

### 6.1 Failure modes

| Trigger | Behaviour | Exact message |
|---|---|---|
| Script run with an unknown flag | exit 2 | `usage: add_license_headers.sh [--check]` |
| `--check` finds missing headers | exit 1, list paths on stdout | `<n> file(s) missing a licence header` |
| A target file is not writable | exit 1 | `cannot write <path>` |

## 8. Verification

```bash
# 1. LICENSE is the real Apache-2.0 text
test -f LICENSE && grep -c "Apache License" LICENSE
# expect: a count >= 1

# 2. Headers present everywhere they should be
./scripts/add_license_headers.sh --check
echo "exit=$?"
# expect: exit=0

# 3. Idempotent
./scripts/add_license_headers.sh && git diff --stat
# expect: no output from git diff --stat

# 4. Generated + vendored untouched
git status --short gen/ | grep -c . || true
# expect: 0
git status --short --  '*node_modules*' | grep -c . || true
# expect: 0

# 5. Nothing broke
go build ./... && go test ./schemas/... && gofmt -l services/ transforms/ pkg/ schemas/ cmd/
# expect: build ok, tests PASS, gofmt lists nothing
```
