# AI Customs Document Preparation for UK SME Exporters — Execution Brief

> Upload a commercial invoice, get a validated CDS declaration draft in 10 minutes — at £12 instead of £48 per declaration.

## Product Vision

### What it does
A web application that accepts commercial invoices, packing lists, and CMR/bill of lading documents, uses AI to extract all shipment fields, suggests correct commodity codes via the HMRC Trade Tariff API, generates a CDS-compliant customs declaration draft, and validates it before the user submits to HMRC's Customs Declaration Service.

### Who it serves
UK-based manufacturers and trading companies with 5-100 employees doing 10-200 import or export declarations per month. Export managers, logistics coordinators, and business owners currently paying £48+/declaration to customs brokers or struggling with CDS manual entry errors.

### Why it matters
CHIEF (the legacy customs system) was decommissioned December 2024. All UK import and export declarations now require CDS-compatible third-party software. UK businesses face £1.8 billion in total customs admin costs annually across 38.6 million declarations. The average cost per declaration is £48. SMEs either use expensive customs intermediaries or make costly manual errors on CDS. No affordable, AI-native tool targeting this gap exists. NI businesses face additional complexity from Windsor Framework dual EORI requirements — see opp-002 for the NI-specific variant.

## MVP Requirements (4-week scope)

### Core features
1. Document upload: commercial invoice, packing list, CMR — PDF and image
2. AI extraction: all shipment fields extracted and structured (consignor, consignee, EORIs, commodity descriptions, values, weights, incoterms, country of origin)
3. Field review UI: display extracted fields, allow inline correction
4. Commodity code lookup: search HMRC Trade Tariff API by description + AI-assisted suggestion
5. Declaration draft: map confirmed fields to CDS import/export entry format
6. Validation: highlight missing required fields, flag unusual combinations, show likely error risk
7. Declaration output: structured PDF or downloadable field-by-field reference for CDS manual entry
8. Declaration history: all past declarations with download links

### User flows

**Flow 1: New import declaration**
1. Upload commercial invoice + packing list
2. AI extracts: consignor/consignee names, addresses, EORIs, commodity descriptions, HS code (if on invoice), invoice value, currency, incoterms, country of origin, net/gross weight, package count
3. User reviews extracted fields (2-5 min)
4. Commodity code lookup: for each line item, AI suggests top 3 UK Tariff commodity codes with duty rates and descriptions — user confirms
5. Incoterms → customs value calculation (AI-guided)
6. Procedure code selection: guided wizard (standard import, customs warehouse, inward processing, etc.)
7. Declaration generated: all CDS fields populated in correct format
8. Validation: red flags shown before user downloads
9. User downloads and uses as reference for CDS manual entry

**Flow 2: Repeat shipment from same supplier**
1. Select previous declaration as template
2. Update: date, quantity, value
3. Re-validate and generate new declaration in under 3 minutes

**Flow 3: Commodity code lookup (standalone)**
1. Enter product description in plain English
2. AI suggests top 5 commodity codes with descriptions, duty rates, VAT status
3. User selects preferred code
4. Can be used without starting a full declaration

## Technical Architecture

### Frontend
- Next.js 14, Tailwind CSS + shadcn/ui
- PDF.js for document preview alongside extracted fields
- Complex form with many fields — use react-hook-form + zod validation
- Vercel deployment

### Backend
- Next.js API routes + background worker for document processing
- PostgreSQL (Railway) for declarations and field data
- Cloudflare R2 for uploaded document storage
- BullMQ or Inngest for async AI extraction jobs (documents take 3-10 seconds)

### Database
- `companies`: id, name, gb_eori, xi_eori, billing_plan
- `declarations`: id, company_id, type (import/export), status, created_at, submitted_at
- `declaration_lines`: id, declaration_id, commodity_code, description, quantity, unit_value, duty_rate
- `declaration_fields`: id, declaration_id, field_name, extracted_value, confirmed_value, cds_field_code
- `documents`: id, declaration_id, doc_type, s3_key, extraction_status, extraction_confidence
- `commodity_lookups`: id, company_id, description, suggested_code, confirmed_code, created_at
- `counterparties`: id, company_id, name, country, eori_number (frequent consignees/consignors)

### API requirements
- **HMRC Trade Tariff API**: Free public API. Returns commodity code descriptions, duty rates, VAT treatment, import/export controls, country-specific rates. No auth required. Rate limits: 1000 req/min — more than sufficient.
- **HMRC CDS API**: For live declaration submission (NOT in MVP — requires developer registration, 4-8 weeks). Start registration on day 1. MVP outputs a validated field reference, not a live submission.
- **Claude API (`claude-sonnet-4-6`)**: Document extraction + commodity code suggestion. Volume: 100-500 API calls/month at launch. Cost: ~£15-50/month.

### AI model usage

**Document extraction prompt:**
```
System: Extract all customs-relevant fields from this commercial invoice or packing list. Return JSON: {
  exporter: {name, address, country, eori},
  importer: {name, address, country, eori},
  invoice_number: string,
  invoice_date: string,
  incoterms: string,
  currency: string,
  line_items: [{description, hs_code_if_present, quantity, unit, unit_value, country_of_origin}],
  total_value: number,
  net_weight_kg: number,
  gross_weight_kg: number,
  packages: number,
  transport_mode: string
}. Mark null if not found. Include confidence per field: high/medium/low.
```

**Commodity code suggestion prompt:**
```
System: You are a UK customs expert. Given this product description, suggest the most likely UK Trade Tariff commodity codes. Return top 3 as JSON: [{code: "XXXXXXXXXX", description: string, why: string, confidence: "high"|"medium"|"low"}]

User: Product: [description], Country of origin: [country], Use: [intended use if known]
```

Use `claude-sonnet-4-6` (not haiku) — commodity codes are high-stakes and require accuracy over speed.

## Data Model

### Core entities
- **Declaration**: One customs entry. Contains all CDS fields in confirmed state after user review.
- **DeclarationLine**: One commodity line within a declaration. Has commodity code, value, origin.
- **Document**: Source document. Immutable once stored. Extraction results reference it.
- **DeclarationField**: Individual CDS field with extracted value, confirmed value, and CDS field code reference.

### Important metadata
- HMRC requires importers/exporters to keep customs records for 4 years. All declarations must be retained.
- Extraction confidence scores stored — useful for identifying which document formats need improvement
- Commodity code history per company — builds up a lookup table reducing future AI calls

## AI Usage Details

### Where AI adds value
1. **Invoice field extraction**: The hardest manual step. Invoices come in hundreds of formats with no standard.
2. **Commodity code suggestion**: HS code classification from product descriptions is genuinely difficult even for experienced customs professionals.
3. **Incoterms → customs value calculation**: AI can guide users through the correct customs valuation methodology based on incoterms (CIF vs. FOB adjustments).

### Where deterministic systems are better
- **Duty rate calculation**: Always use HMRC Trade Tariff API rates — never AI estimates
- **Procedure code logic**: Rules-based wizard (not AI) — wrong procedure codes trigger audits
- **CDS field formatting**: Strict format validation (date formats, EORI format, commodity code digit counts) — deterministic regex validation
- **Declaration completeness check**: Rules-based required-field validation

### Key risk management
Customs declarations are legally submitted to HMRC. Errors have real consequences (penalties, delays, audits). Position the product clearly as a **preparation and validation tool** — the user is always responsible for reviewing and submitting. Include this disclaimer prominently in onboarding and on every declaration output. Never offer automated submission until the product has processed 500+ successful declarations with <1% error rate.
